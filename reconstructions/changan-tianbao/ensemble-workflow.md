# 建筑群复原工作准则

[天宝长安项目入口](README.md) · [建筑群复原模板](ensemble-template.md) · [坊市资料构建工作准则](ward-workflow.md) · [荐福寺浮图院示例](jianfu/README.md)

**模板规定成稿写什么，本准则规定怎么查、怎么成图、何时可以交付。** 里坊资料解决坊内区位与街巷关系；建筑群专项往下查到院界、出入口、单体和构件。荐福寺是证据处理的例子，不是每个专项都要配齐的文件或图纸清单。

## 一、开工时确定范围

1. 确认**对象、目标时点和交付用途**：仅做考证，还是也交展示方案。天宝长安用天宝九载（750）作参照；史料、遗存和测绘各写实际年代，不统一标成 750 年。
2. 先看项目入口、工作区、已有编号和上游坊级资料。分清同名对象、历史归属与场景裁切，列出本次要深查的单体及不纳入之处。上游引用固定版本；未配准时，不从坊级示意图抄坐标。
3. 对同名对象或范围确有歧义时先确认。没有上游专项、既有模型或齐全图件不妨碍先做考证；注明缺项，沿用现有目录和编号。

可直接交给 Agent：

> 按《建筑群复原工作准则》和《建筑群复原模板》整理〈建筑群〉在〈时期〉的复原资料。核查区位、分期、院内关系和重点单体的平立剖；把可核依据、推定和展示取值分开写入专项 `README.md`。有依据才落位，能交正式总平面时交源数据和同源布局图；否则留占位并说明待查资料。

## 二、网上查找：先定位，再追形制

1. **从名称、归属和沿革入手。** 用古称、今名、异体字、所在坊名和建造者交叉检索；通读地志、辑考、碑志或笔记的上下文，再追所引原书。百科、馆方简介和新闻可找线索，不代替原文。
2. **并行追查三条材料线。** 文献和碑刻查营建、修缮、毁损及院内对象；考古报告和修缮档案查遗迹编号、平面、地层、构件和尺寸；历史图像、现状照片和专业研究查失落形制、后补部位及争议。优先看可辨读的图版、测绘立剖和对应说明，不从图名、缩略图或新闻配图补细节。
3. **按会改变复原的属性复搜。** 用「`对象名或异名`＋测绘／修缮／立面／剖面／发掘图版」「`部件名或原文短语`＋碑记／营建」等组合。先查院门、边界、轴线等总图约束，再查会改变单体轮廓、通行、构造或断代的属性，不把精力耗在无依据的小装饰上。
4. **追来源链，不数转载。** 回核卷篇页、碑刻释文、图号或遗迹号；区分正文、原注、后加续注。遇缺页、付费墙或不可读图版，试替代版本；仍不能核的，写明查到哪一级。没有联网或无法打开原件，不报已核。

## 三、从证据到方案

逐项记录：**对象／部位｜具体主张｜原文或图版所见｜出处和定位｜材料时间｜所述阶段｜核验状态｜能支持的精度及边界**。记录直接整理进主文、单体详条或来源索引，不另要求交检索日志。

- **先分期再采用。** 对象存在、具体位置、构造和尺寸分别核查；同址现存不等于目标期原样。后世加建、维修和残损单列；类比说明可比的年代、功能或部位，不用来证明本址存在。
- **先写可确认的关系，再落平立剖。** 院门朝向、门址和门塔同轴分别判断；坊墙、院墙和场景边框分开。单体按部件核对存段、后补和失段；看不见的内部不为闭合剖面补出楼板或基础，不能把一个立面复制到四面。
- **分开记录发掘所见、发掘者解释和本项目取舍。** 先记录发掘编号、图号、遗迹所见及量取口径，再记录发掘者对归属、年代或功能的解释，最后说明本项目采用到哪一步。遗迹尺寸明确，不等于归属或年代已定。例如，[安仁坊北墙角门](jianfu/sources.md#jf-s13)距坊西北角约 13 米；发掘者推测它是浮图院便门，但尚不能据此给文献所记的北开院门落坐标。
- **每个关键数字可回溯。** 写原单位、起止测点、标高或边线基准、取值方法和采用理由；测绘转引与实测分开，图像估算无定标或量取记录就不作尺寸依据。冲突值先并列核口径，不用平均值掩盖异说。
- **把空白写清楚。** 按模板区分「原文未载」「已查未见」「尚未查核」和有根据的排除；展示占位登记理由、开关和撤换条件，不当证据。拿荐福寺来说：文献有北开院门及隔街对向，不等于能定门址；现代残高也不是天宝塔的总高或某一级檐标高。

## 四、目录与文件

```text
reconstructions/changan-tianbao/<建筑群目录>/
├── README.md        # 必需：A／B／C 汇编及总平面入口或占位
├── data/            # 有正式程序化总平面时：GeoJSON 与渲染清单
├── figures/        # 按需：可引用的关系图、立剖或节点图
└── <专题>.md       # 按需：值得独立阅读的单体卡、来源等
```

- 主文默认写完；来源多、逐级参数供下游读取或确有独立资产交接时才拆。图、表与对象使用同一编号，不要求固定数量的附件；不要为同一几何维护两套数据。
- 关系图、历史资料图、展示工作稿、模型截图分别标明阶段和用途。保留既有图件和引用，不用试点覆盖正式交付。下游引用固定版本；大资产只记录版本、链接与上游依据。

## 五、总平面、GeoJSON 与本地预览

**能成正式总平面时，交 GeoJSON 和由它生成的布局图。** 源数据和清单进仓库，推荐 `data/ensemble-plan.geojson`、`data/manifest.json`；README 的 A2 写坐标基准和图版入口，C2 说明量取限制、生成方法及未定位对象。布局图可在本地生成 PNG 检查，不提交 PNG 或缓存，也不强制生成或提交 SVG。沿用[绘图器指南](../../scripts/ward-render/README.md)的字段和清单格式，建议清单的 `id` 与 `output` 的文件名（不含扩展名）都用 `ensemble-plan`。

| 证据支持到哪一步 | 怎么交 |
| --- | --- |
| 只知对象存在，或布局整体未定 | 主文留文字占位；若有相对关系，可用既有或不按比例的关系图占位。不建空 GeoJSON，不造点位。 |
| 部分对象可定位，有足够依据成局部总平面 | 只画已知点位、边线或有明确前提的推定范围；未定位对象留在 A2 或附表，不给假轮廓，不闭合未知院界。 |
| 有可核尺度、位置与边界依据 | 按证据精度落位，区分可量取与仅示意的部分；标来源、原点、轴向、单位、配准状态。局部米制不当经纬度，不因单体尺寸有据就给整院比例。 |
| 只有灰模、类比补足或异期布局 | 保留为独立工作稿或备选图，不混入正式总平面，不把展示坐标当考古坐标。 |

绘入 GeoJSON 的要素用稳定 `id` 对应 A2 对象编号，可拆分为可追溯的子编号。`source` 指向具体出处，`grade`、`position_precision`、`inference` 分别反映这项主张的证据等级、定位精度和几何依据；不把「院门存在」的证据等级转给它的坐标。方向未定不标北，示意位置不标历史比例尺。单体平立剖、逐级或节点图按需提供，不必转为 GeoJSON，也不要求成套。

有正式图时，从仓库根目录执行（替换 `<建筑群目录>`）：

```bash
pnpm render:ward --manifest "reconstructions/changan-tianbao/<建筑群目录>/data/manifest.json" --check
pnpm render:ward --manifest "reconstructions/changan-tianbao/<建筑群目录>/data/manifest.json" --png-dir "build/figures/agent/changan-tianbao/<建筑群目录>"
```

打开生成的 PNG，检查标注是否可读、未知边界是否被画实、关系注记是否像精确落位、图例能否区分有据和推定。只有占位时，检查占位文案和相对链接即可，不运行渲染。

## 六、何时达到可交付深度

| 检查项 | 达标表现 |
| --- | --- |
| 范围与分期 | 区分目标期、后世改修、现状测绘及展示裁切；坊级区位和本专项范围不混淆。 |
| 布局与对象 | 查过院界、出入口、相关街巷、院内关系与地坪；对象总表能区分已定、未定位和异期，图或占位与文字判断一致。 |
| 单体与证据 | 核心单体的平面、分面立面、剖面、材料与构造可逐项追据；足以改变轮廓或断代的争议有出处、未核状态和下一步线索。 |
| 制作与图版 | 有展示交付时，从图或模型说明抽一项关键取值追到基准、出处或制作理由，确认占位可撤换；有正式布局图时确认源数据通过校验、同源 PNG 已打开核图。 |
| 入口与交接 | 项目入口、相对链接、锚点及编号可互查；未解决事项说明影响对象、图版或资产。 |

完成核心问题的检索与核查后，如果再查只重复同一来源链，或关键档案暂不可得，可交带缺口说明的稿件。用 A4 记录**已查哪里、还缺什么、下一步去哪找**；核心方向还没查则标阶段稿，不靠附件数量凑完成度。交付时报告文件、查核范围、主要结论、限制和验证结果；代码或配置改动按仓库规范运行 `pnpm check`。
