# 坊市资料构建工作准则

[天宝长安项目入口](README.md) · [里坊资料汇编模板](ward-template.md) · [平康坊成稿示例](pingkang/README.md)

本准则与[里坊资料汇编模板](ward-template.md)配套，供 Agent 从网络查找、核验并汇编一个唐长安坊市的复原资料。**模板规定成稿写什么，本准则规定怎么查、怎么判断查够了、怎么落成文件。** 平康坊是研究深度的参照，不是条目数量、文件数量或制图数量的指标；不需要先读平康坊才能执行本准则。

## 一、开工时确定范围

最低输入是**目标坊市名和复原时期**；时期若已由项目确定，不必重复询问。天宝长安项目默认讨论天宝年间，以天宝九载（750）为参照，不把这个参照点当成所有材料的事件日期。若同名地点无法区分，或项目与任务指定时期冲突，先确认再建目录。

可直接交给 Agent 的任务示例：

> 按《坊市资料构建工作准则》和《里坊资料汇编模板》，为唐长安〈坊市名〉整理〈时期〉复原资料。上网找来源、打开原文或报告核对，把成稿写入对应坊市的 `README.md`；有依据的信息尽量收录，不确定的标明状态，不为了配图补位置。交付时报告已覆盖的范围、仍缺的关键材料和下一步可查出处。

在已有仓库中，先看项目入口、目标目录、工作区和已有编号，优先更新现有资料。只有两份规范时，可以先用目标坊市名和时期开展研究，不以拿不到通用手册或旧示例为由停工；无法联网时据实说明，不声称完成了网上查核。

## 二、网上查找：先打底，再追对象

**尽量查全与目标坊市有关的材料，有依据的信息尽量收录。** 模板是组织材料的最低骨架，不是检索上限；栏目填满、已有材料足以出图，都不是停止条件。新发现的关键对象继续追查，不能落图的官职、沿革、活动、壁画及器物等资料也纳入汇编；异期、冲突与未核线索注明各自状态。

1. **从百度百科找第一批线索。** 先搜 `〈坊市名〉 唐长安 site:baike.baidu.com`，打开条目，确认说的是唐长安的同名地点。扫读正文和参考资料，把坊名异称、所属县、邻坊、门街、寺观宅第、人名和引用书目记成**待查清单**；年代或方位互相冲突的说法也先留下，不照抄入稿。找不到单独条目时，可查唐长安城总条、邻坊条目，或直接进入下一步，不把百科当作必经来源。
2. **用地志和辑考校正、扩充清单。** 搜 `〈坊市名〉 长安志`、`〈坊市名〉 唐两京城坊考`，用繁简、异体字和旧名复搜。通读坊市总条、邻近条目及上下文，再追所引原书；用邻坊、路名或城门名反查四至。核对百科线索，也补查原书里有而百科没提到的对象、日期和方位。
3. **并行追三类材料。** 地志、正史、会要、碑志、笔记等用于追对象与沿革；考古报告、简报、图版和馆藏目录用于找本址实证；论文和专业著作帮助查原始出处、争议与同类参照。每条路线按目标坊实际材料取舍，不以某一路线空白否定其他路线。
4. **按对象和问题二次检索。** 用「`坊名`＋发掘／遗址／简报／图版」「`对象名或异名`＋旧宅／墓志／置观／寺塔」「`原文短语`＋书名」等组合，追到卷、篇、页、图或遗迹号。重点复核会改变本期布局或解释的主张：坊界、门街、可落位对象、关键院内关系和存续年代。
5. **追读而非计票。** 对二手文章给出的书目、脚注、图注和释文，尽可能回到原件；多个网页转载同一出处只算一条来源链。百科、自媒体、搜索摘要或生成内容只能帮助发现线索，不能代替可核出处。遇链接失效、付费墙、缺页或只有 OCR 时，尝试替代入口或版本；仍看不到就登记未核范围，不写作已核，也不把 OCR 疑字默改为定文。

## 三、每条材料怎么记、怎么入稿

检索时逐条记录：**对象或事项｜具体主张｜原文短引或图版所见｜出处及可访问链接｜成文／报告年代｜所述事件或遗迹年代｜查核状态｜方位精度｜能支持什么、不能支持什么**。出处尽量写到作者、书刊或机构、版本／卷篇／页码／图版／遗迹号；网络馆藏记录无页码时，用馆名、藏品名和馆藏号或稳定页面定位。对图版只有看过可辨读的图或报告正文，才记录其实际所见；不要从论文标题、缩略图或图名补出细节。工作记录可直接整理进主文和引用总目，不要求另交检索日志文件。

- **先按主张核对，再判断是否可用于本期。** 同一条可支持对象存在，不一定支持坐标、产权或延续到参照年。后世成书的资料可能追记本期事件，关键是说的哪一年、哪一阶段；明确异期的内容保留在沿革、详条或旁证，不当作本期现状。
- **把方位词留到原有精度。** 某隅、某门一侧、相邻、仅坊市内是不同精度；不要换算成精确点位。几条相对关系不自动构成完整路网或闭合院界。争议要把原说、出处、口径和尚不能判定之处并列；尺寸折算需交代原单位与换算假设，不写成实测。
- **按模板分开原记载、转引、待核和推导。** 名称、修造、用途、墙面、器物、花木等有依据就收，不局限于能画上图的资料；地点或时代关联不明的线索可留作待核。制度和同类案例只说明可借与不可借，不给本址补默认尺度。图上留白不等于没有建筑。
- **发现缺口要写清查到哪一步。** 看过某篇没写是“原文未载”；查过说明范围仍无结果是“已查未见”；找到了出处线索但未能核对是“尚未查核”或“转引（未核）”。只有有依据证明本期、该范围内确实不存在，才写“本坊无／本市无”。

## 四、目录与文件

一个坊市目录对应所属复原项目的一个时期，不另设分期目录和分期图。沿用现有目录名；新建目录时按项目现有命名惯例，只创建本次实际使用的文件。

```text
reconstructions/changan-tianbao/<坊市目录>/
├── README.md       # 必需：总入口与 A／B／C 汇编
├── data/           # 有程序化平面图时才建，存 GeoJSON 与清单
└── <专题>.md       # 可选：材料较多、需要独立阅读或维护时拆出
```

- 默认在 `README.md` 写完汇编。对象总表、主要证据、院落细节、引用和图版状态都应从总入口可查。专题、证据 CSV、底图说明或源数据有具体用途才增加；不要为同一结论维护几份互相独立的正文。按需更新项目入口，使新坊市可找到。
- 只按模板登记两类平面图：**坊市平面分布图**合绘骨架和对象，周边区位就地表达或引用既有全城图，资料不足可用文字占位；**院落内部图**有空间关系才逐院独立成图，以对象编号互引。只知名称或没有位置关系的写在文档里，不画假平面；有相对关系、无可靠尺度的可画不按比例示意。
- 区分本版采用图、旧档和试点，不用试点覆盖已交付图。保留已有对象号、来源号和外部入链；改名、移动或改号前先查引用。大资产按仓库约定留版本与链接，不直接入 Git。

## 五、GeoJSON 平面图与本地预览

**先系统检索、整理证据，再集中制图。** 从检索记录中筛选空间信息，不以正文已经定稿或逐条写入为前提。用于制图的主张必须可从 GeoJSON 的 `source` 或图版说明回查，并说明年代、方位精度和推导限制；发现矛盾时回查史料，不为填图补位置。

新制平面图以 `data/ward.geojson`（坊市主图）、`data/courtyards/<对象短名>.geojson`（逐院独立）和 `data/manifest.json` 为交付源文件。主图待定时只留文字占位，不建空数据。**不要求生成或提交 SVG**，也不删除既有 SVG。

- **输入怎么写：** 按[绘图器输入格式](../../scripts/ward-render/FORMAT.md)编写 GeoJSON 和清单，可参照[可运行的最小示例](../../scripts/ward-render/examples/manifest.json)了解结构，不照搬示例坐标。图元的点、线、面坐标，以及需要手动指定的标注位置，都写在 GeoJSON 中；绘图器不从方位词推算位置，也不按年代字段自动筛选图元。
- **输出怎么生成：** 按[绘图器使用指南](../../scripts/ward-render/README.md)生成并打开本地 PNG。文件名由清单中的 `outputs[].id` 决定，即 `<id>.png`；`output` 和 `size` 只供旧版 SVG 导出，新制 PNG 不填。PNG 和缓存不入 Git。

### 先判断能画什么，再判断置信度

制图前对照正文、对象总表和可辨读的原始图版、图注或测量记录，盘点**坊界与墙段、门街、四隅、邻坊、发掘点、对象方位、总体与局部尺寸**。逐项判断上总图、上院落图、留图旁还是待核；不要求另交清单文件。

| 依据支持的空间信息 | 正式资料图的表达 |
| --- | --- |
| 只知某对象在坊内或院内，不知位置 | 保留在对象总表或院落清单，标“在内，位置不明”。已有绘图数据时列入 `data/unplaced.csv` 并在图版说明引用；不加点、方框或假坐标。未定位清单不是图上的落位图层。 |
| 只知在某隅、某门一侧或相邻 | 在相应区域或参照物一侧放置符号或占位块，注明更细位置未定。占位不代表建筑坐标、院界、距离或同隅对象的先后次序。 |
| 有点位、走向或边界依据 | 按证据精度画点、线、面；只知局部边线就只画该段，不补闭合地块、轮廓或尺寸。 |
| 有相互竞争的落位解释 | 各自有依据且能示意时，标为备选并各自给出处，不合并成一个确定位置。 |
| 方位有据，但本期存续待核；或明确异期、属于出土记录 | 可按已知方位画符号、占位或注记；用图例和就地标注明确区分本期待核、异期旁证或出土发现。不把异期对象画成本期现状，不把出土点当作原使用地点。 |
| 关键出处未核，或只有无本址依据的补足 | 留在文档、待核清单或独立标明的试点，不当作本期实证。 |

- **证据等级、方位精度、绘入几何的依据分别判断。** `grade` 用渲染器要求的 A/B/C/D，对应模板的甲/乙/丙/丁，按图元所表达的具体主张填写；`position_precision` 表示落位精度；`inference` 表示绘入的几何是直接有据还是推导等。用 `source` 指回可核出处，图元使用稳定 `id`，对应对象须能与 A2 编号互查。
- **推导可画到所支持的精度。** 有明确前提的较可能关系或备选范围，可按绘图器的 `likely`／`alternative` 样式区分，图例和说明交代依据；没有定位前提就不画，即使对象存在本身十分确定。仅可排除的结论不转换成一个正面落位。图面线型和灰阶说明复原依据，不是证据等级或置信百分比。
- **先画骨架，再加对象和标注。** 复原示意优先选简单可通行的布局，如直街接门，不因历史线位待核而断开已画的门街，也不为避免暗示共轴而任意加转折。就图说明接法是示意。考古实证部分保留实见墙段、门道及缺口，不为闭合或连通补画遗迹。
- **逐项核尺寸与方向。** 核对每个数字的方向、端点和量取基准，区分实测残长、推定全长和文献折算。有依据的总体长宽可用 `layer: "dimension"` 画尺寸线，写入两端界线和读数标注；墙基尺寸、角门距角等标在对应构件旁，让读者知道从哪里量。局部米制需要可靠尺度；只有相对关系时用示意坐标，不标比例尺，方向未知时在清单关闭指北针。不要把一个已知尺寸扩展为整张图都可量取。

例如，原文明确说“某寺在坊内”，寺的存在和归属可标甲，但寺仍只列未定位。若另一条材料明确说“寺在坊西南隅”，就放入西南隅并标“隅内未定”，仍不能画寺界。如果西南隅只是根据邻接关系推得，就用推导样式并注明前提，不把它标成原文记载。

### 渲染与验收

从仓库根目录执行（将 `<坊市目录>` 换成实际目录名）：

```bash
pnpm render:ward --manifest "reconstructions/changan-tianbao/<坊市目录>/data/manifest.json" --check
pnpm render:agent
```

PNG 在 `build/figures/agent/changan-tianbao/<坊市目录>/` 下。也可按[绘图器指南](../../scripts/ward-render/README.md#只生成需要的图)只生成需要的图。打开实际 PNG，对照制图前的盘点逐项验收：

1. **内容和空间关系：** 有方位的对象是否漏画，四隅是否在对应方位，邻坊和发掘点是否标对；示意门街能否走通、有无穿墙，考古墙段有无被补成闭合边界。
2. **数字和读法：** 总体尺寸线两端是否指对边界，局部尺寸能否看出量取基准；无需翻正文也能分清实证、试绘方案、本期待核、异期和出土旁证。关键限制直接标在图上；“只确认哪些门”不能被读成“确认只有哪些门”。
3. **排版：** 检查尺寸读数、发掘标签、邻坊名及其他标注是否压字、被裁切或容易认错对象。需要调整就改 GeoJSON 中的几何或标注坐标，再生成 PNG 复查。

`--check` 通过只说明数据可读取，不能替代验图。

## 六、何时达到可交付深度

以**覆盖了哪些问题、能否复核**为准，不用搜索次数、来源数量或建筑数量充当完成度。交付前逐项检查：

| 检查项 | 达标表现 |
| --- | --- |
| 坊域 | 已查区位与四至、边界与尺寸、门街、地块及相关环境；有依据的信息都落文，关键空白说明查到的范围。 |
| 对象与关系 | 已顺着坊市总条和相关来源追查可识别对象及活动，不只写最著名的几处。对象总表可区分本期可用、待核和异期，关键邻接或院内关系可追到详条。 |
| 证据与争议 | 可改变布局或时点判断的主张已优先追原文、报告或图版；可核的有短引或可定位出处，不可核的有状态和下一步线索。冲突、弱线索及推导没有写成确定事实。 |
| 图版与入口 | 坊市主图或占位已登记，院落图按依据取舍。有 GeoJSON 的图通过校验且打开本地 PNG 检查过，图面不超过证据精度。项目入口、主文和附页链接可用；本地 PNG 标明生成方式。 |

完成总条与邻接材料的检索、逐项追查主要对象和关键争议后，如果再查只出现重复转载、未开放材料或无法继续验证的同一线索，可以交稿，不必为填空无限搜寻。用 A4 说明**还缺什么、查过哪里、下一步到哪找**。如任务时限内只完成部分检索，交付时明确标为阶段稿，列未覆盖的方向，不以“已经达到平康坊程度”替代说明。

最后报告改动文件、查核范围、主要发现、未解决事项和验证结果。文档改动检查入口、相对链接、锚点及引用编号；代码或配置变动按仓库规范运行 `pnpm check`。
