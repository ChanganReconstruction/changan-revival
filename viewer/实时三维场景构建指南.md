# 实时三维场景构建指南

适用于浏览器、游戏引擎中的实时城市、园区和景观场景。目标不是让每件物体同样精细，而是让场景从实际观看距离看得懂、走得通、改得动，并在目标设备上流畅运行。

## 1. 开工前：先定用途、尺度和预算

- 确定主要用途：全景展示、地面漫游，还是贴近查看。约定最近、最远镜头和可到达区域；镜头永远看不到的细节，不列入首版。
- 统一世界单位、朝向和高程基准。用人物、门洞、台阶等已知尺度校对街宽、院深和檐高，不凭鸟瞰画面整体放大房屋。
- 确定目标设备、分辨率和画质档，选定固定鸟瞰、正俯视、地面和逆光机位。先用样板测帧时间，再定绘制批次、几何、纹理和阴影预算，不套用别的项目的数字。
- 还原类项目把资料分成可靠事实、合理推定和艺术处理。可用参考图校对相对位置和比例，但不能把示意线当测绘坐标。

## 2. 白模：自然环境与建筑一起落位

先用低细节体块搭出地形、道路、水系、树群和主要建筑。此时不做窗棂、瓦纹或装饰。先验证这些关系：

| 对象 | 白模阶段就要检查 |
| --- | --- |
| 地形 | 坡向、台地和地平线是否合理；建筑、道路和台阶是否落地，近处坡折与远处山脊是否有层次。 |
| 道路 | 主街、支路、巷道能否辨认；路口和桥头能否接上，人在地面视角能否读懂走向。 |
| 水系 | 来水、去向、分流、水位及宽窄是否说得通；岸坡、桥涵和出口是否真的连通。没有依据的上游或支线可以省略，不用硬连。 |
| 植被 | 按坡地、水岸、院落和使用方式成片或成带布置，避免均匀撒点；留出通行与关键视线。远山、林缘和开阔地也要参与构图。 |
| 建筑 | 看占地、进深、檐高、屋坡、台基和院落净空的关系。高低差用于区分低宅、大殿和楼阁，不靠统一拉伸。 |

**选一个完整区域做样板**：最好有街道、高差、建筑和树或水，同时包含鸟瞰和近景。先把布局、材质、日照、接地阴影和性能一起跑通，再扩到全场景。单栋房屋做得好，不能证明整片场景能成立。

## 3. 构图、色彩与疏密：避免平均用力

- **布局有主次。** 先定主轴、视觉焦点、次级节点和留白，再组织街坊。正俯视检查地块是否在重复同一图案；低角度看天际线、前后遮挡和焦点是否清楚。
- **疏密有理由。** 商业可沿街连续布置，住宅用不同院落组织聚散，园林与水岸可留开敞空间。留白应服务于通行、视线、仪式或自然地形，不是简单随机删房。大殿也需要与前场、台基和侧翼一起判断体量。
- **变化靠组合。** 优先变化地块大小、巷道走法、院落围合、进深、退距和组团高度；其次才换屋型、颜色和装饰。共享构件不等于共享整坊的构图。也不要每处都随机变化：轴线、沿街界面和同类建筑仍需有一致性。
- **颜色有层级。** 大面积墙、瓦、土石和植被用克制的底色；用有限色组做区域的冷暖、明暗差异，把较强对比留给焦点。避免整城一个色，也避免逐栋随机上色。贴图底色、材质色和实例色会相乘，检查最终画面，不只看色卡。
- **纹理要跨尺度检查。** 近处有用的瓦纹或草地细节，远看可能形成条带、棋盘或噪点。近景保留细部，中远景优先保住大块颜色、轮廓和材质差别。

**按三轮看图：灰模看布局和体量，色块看区域和焦点，实际光照看材质与阴影。** 如果灰模已经单调，先改构图；如果只在暖光下泛黄，先排查光色与材质叠乘，不要直接把全场换色。

## 4. 光照、阴影和氛围

- 先用一个明确的主光和天空补光定白昼，再做暖光及夜景。太阳盘、主光方向和阴影方向应一致；雾用来表达远近，不用来遮布局和地形接缝。
- 阴影首先负责接地和读形。优先检查台基、桥脚、檐下和建筑之间的影子；不是所有窗棂、树枝都需要投影。调整阴影覆盖范围、分辨率和偏移时，同时检查阴影剥离、表面条纹与镜头移动时的闪烁。
- 静态场景可复用阴影。只有光向、投影物或阴影覆盖范围变化才重算；若用随镜头移动的阴影范围，需检查跟随时是否跳变。日夜转换则要验证天空、照明、阴影和窗灯一起更新。
- 用同一机位比较白昼、暖光和逆光；开关阴影各看一次。能区分是体块没接上、阴影没贴住，还是材质对比不足。

## 5. 怎么构建、怎么修改

1. **总平面数据**保存地块边界、道路中心线、地标锚点、水位、地形与稳定编号。地图、标签和机位尽量读取同源数据，避免各模块再写一套世界坐标。
2. **局部布局规则**根据地块类型和尺寸生成院巷、建筑占地、留空区和树位。规则先产出可检查的布局，再交给三维装配。不同地块、建筑和植被各用稳定种子；迁移旧规则时，注意随机数调用顺序可能改变无关区域。
3. **构件与渲染**负责把布局变成几何、材质和批次。背景建筑共享构件，通过实例调整长宽高、朝向和色调；地标独立设计有识别力的部分，仍可复用通用材质和零件。需要调整比例时，檐高、屋坡和台基分别控制。
4. **修改先定位层级。** 整个街区比例不对就改总平面，坊内重复就改布局规则，某类屋坡太尖才改原型。改水位、路宽或地标位置时，列出桥涵、岸线、标注和机位等依赖，验证一起更新。

实践流程：**留 Git 基线与同机位截图 → 做可回退的小改动 → 跑对应几何测试 → 看实际画面 → 集中回归。** 不要用新几何遮旧错误。例如造桥先给原路留出真缺口，再接桥面、河岸和两端坡道；测试应探测最终场景，确认桥下没有原路面、水能贯通，而不是只断言参数里设置了“开口”。院坪被地基盖住、台阶悬空、屋面法线反向，也适合用相交、标高或法线测试提前发现。

## 6. 优化：先分清瓶颈，再动手

| 成本 | 优先办法 | 不要误读 |
| --- | --- | --- |
| 绘制提交 | 普通建筑共享几何和材质、按空间分批实例化；不为每种颜色或微小尺寸差异复制原型。 | 实例化不自动减少三角面。分块过细会涨调用，过粗又会一起绘制大量看不见的物体。 |
| 几何与远景 | 近景用必要的实体结构，中远景以门窗贴图、简化树冠或裁切卡片替换；切换加滞回。 | 分级是替换，不是多套叠画；也要检查正俯视，不让只有竖片的远树消失。 |
| 像素与后处理 | 独立设置三维渲染比例，界面保持原生像素；按档位裁减昂贵的屏幕后处理。 | 宽高 70% 约为 49% 像素，不代表几何和阴影成本减半，也不等于帧时间减半。 |
| 阴影与重复绘制 | 限制投影物和覆盖范围，固定时复用阴影，静止场景按需渲染。 | 首帧建阴影、镜头移动与缓存帧分开计量；静止零提交不是高帧率。 |

**项目实测案例：**同一全城机位将屋坡变体从四档收敛为两档后，缓存帧绘制调用由 **415 次降到 348 次**，三角面仍为 **306,572**。收益来自减少批次拆分，不是减面。对比时保持机位、画质、分辨率和阴影缓存状态一致。软件渲染可查功能和成本变化；设备流畅度要在真实目标设备上测，最好分别记录巡游、旋转和静止状态的帧时间。

## 7. 长安实战：哪些地方该省，哪些不能省

### 普通街坊：省构件，不省立面信息

早期做法是把柱梁、窗格整批按距离隐藏，结果远处的房子像没有门窗的白盒。后来让门窗明暗、檐下横梁和竖柱节奏常驻在共享立面贴图上，只在重点坊区的近景保留实体细节。判断标准是：**只影响平面明暗的细节优先用贴图；改变外轮廓、转角视差、通行或投影形状的结构保留几何。** 瓦纹可以画，屋檐要有轮廓；门板可以画，能从中穿过的城门不能画在墙上。切换远近档时，用同一条街同时检查门窗是否仍可读、几何是否有重复叠画。

长安另提供 **100% / 85% / 70%** 三档三维渲染比例，与画质档独立。85% 约绘制原来的 72% 像素，70% 约 49%，文字和控件仍按原分辨率显示。实际顺序是：在同一机位先试 85%，看细瓦、树缘和屋檐是否明显变糊，再决定是否降到 70%。如果瓶颈在绘制批次、几何或阴影重算，改这些环节，不能指望降低分辨率解决。验证时既查画布实际渲染尺寸，也查切换画质不会重置比例、不会改变植被的远近分级。

### 重点景点：远处认轮廓，近处看结构，与周边拉开层次

| 景点 | 不能用通用建筑替代的部分 | 与周边拉开层次的方法 |
| --- | --- | --- |
| 明德门 | 五条实体门道和连续门台；检查门洞从前到后都畅通。 | 用朱雀轴线、门前开敞空间和两侧连续城墙突出入口，不靠把门楼涂得更亮。 |
| 含元殿 | 主体十一间与周匝副阶的关系、高台和两侧盘道，不能简化成一座放大的住宅。 | 从丹凤门方向看前场、台基、侧翼与主殿的递进；两翼应衬托主殿，不能把仪仗空间填满。 |
| 大、小雁塔 | 分别做楼阁式层级与密檐式收分，不用同一塔身换层数。结构识别不等于确定了历史尺寸。 | 给塔保留清晰的天际线，以低殿、院落和树群作尺度参照；近看才把预算给入口与砖檐。 |

这些例子不是要求景点全面加面数。先保住**轮廓、空间关系和辨识度**，把额外细节给主要接近路线、观景面和停留范围。过渡区用中等体量、植被和材质承接，背景继续复用简体模型；重点建筑也可以和背景共享瓦材、墙材和重复构件。

### 返工记录：局部好看，不代表总平面正确

| 怎么发现 | 做过什么 | 仍需注意什么 |
| --- | --- | --- |
| 正俯视下，许多坊仍像同一图案平铺。 | 用不同巷道、院落、绿地和疏密打散坊内构图，减少北部重复坊。 | 外部坊界仍主要来自固定行列；大小不一、合并地块及两市与宫苑的比例，要在总平面解决，不是再换一批屋顶。 |
| 含元等单体更能认出，但鸟瞰下宫苑位置和占地比例仍显别扭。 | 重做部分殿阁、盘道和前场，改善局部体量。 | 太极宫、皇城、大明宫与兴庆宫尚未按统一底图校正；总平面改造仍是计划，不算已完成。 |
| 曲江像椭圆水片，早期甚至被坊墙切断。 | 改为非对称岸线，补岸坡、岛与临水空间，为黄渠入池末段留出真实开口。 | 这些是示意线位和艺术尺度，不是历史测绘；局部连通不等于完整水网已经建成。 |
| 西侧渠段加入后，两条原来约 13 米宽的模型街道变成约 6 米宽的路带。 | 保留道路通行，做真实过街缺口、桥面和接坡；现方案基本保留，不再大改渠线。 | 桥能过、水能通，不能证明沿街渠位和道路断面合乎史实。以后先把坊界、街宽、渠岸放在同一张断面图核对，别让新增水体悄悄吃掉原道路。 |

## 8. 可带到新项目的检查清单

**开工**
- [ ] 已确定用途、观察范围、单位、目标设备和固定验证机位。
- [ ] 总平面和白模包含地形、道路、水、树群与重点体块，不只包含建筑。
- [ ] 一个代表区域已验证布局、色彩、光照、阴影和性能，可供全场复用。

**交付**
- [ ] 正俯视看不出机械复制；低角度有体量层次，地面视角通行与视线清楚。
- [ ] 白昼、暖光和逆光下，材质分得开，阴影接地，远近层次自然。
- [ ] 关键桥涵、水岸、平台和台阶通过几何检查；史料推定和省略部分已说明。
- [ ] 距离分级、画质切换、日夜和交互通过浏览器或引擎实测；版本与截图可复现。
- [ ] 构建、几何、视觉和性能分别有验收结果；首帧与缓存帧分账，未测的设备明确标注。

**总结：先做可检验的空间关系，再做整体色彩和光影，最后把细节与渲染成本投到最值得的地方。**
