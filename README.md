# 唐长安城数字复原项目简介

## 1. 项目概述

**项目名称：** Changan Revival  
**项目仓库：** `changan-revival`

本项目旨在基于历史文献、考古资料及相关研究成果，对唐代长安城及其108坊进行数字化复原，最终构建一个兼具历史依据与视觉表现力的三维城市漫游系统。

项目不仅关注城市整体布局，还包括坊市内部空间、道路、院落、建筑及重点历史遗迹的复原。

整体采用**史料约束下的几何建模 + 城市级视觉制作 + 局部生成式高精度场景**的混合技术路线。

核心目标包括：

- **历史可信：** 复原结果尽可能具有史料或考古依据，区分确定信息与推测内容。
- **城市完整：** 构建包含108坊、道路、城墙及重要建筑的整体三维场景。
- **分级精度：** 全城采用相对简化的Mesh，重点建筑采用更精细的几何及材质表现。
- **视觉表现：** 通过材质、贴图、光照与环境设计形成统一的唐长安城视觉风格。
- **局部增强：** 使用世界模型生成的3DGS及视频，为重点区域提供高真实感体验。
- **交互展示：** 支持城市级自由漫游，以及普通Mesh场景与局部3DGS场景之间的切换。

## 2. 整体技术架构

项目采用分层架构，按照数据和资产的生产过程组织：

```text
历史文献 / 考古资料 / 历史地图
                │
                ▼
          Research（史料层）
        史料检索、证据分析
        空间与建筑形制复原
                │
                ▼
        结构化历史复原数据
                │
                ▼
          Geometry（几何层）
         坊市与建筑几何建模
         程序化生成、白模构建
                │
                ▼
          城市基础 Mesh
                │
         ┌──────┴────────┐
         ▼               ▼
    Visual（视觉层）   Generative（生成层）
    材质、贴图、环境    世界模型、3DGS
    重点建筑精细贴图    局部场景生成
         │               │
         └──────┬────────┘
                ▼
       Transitions（过渡层）
       相机匹配、过渡视频
       Mesh与3DGS场景衔接
                │
                ▼
          Viewer（展示层）
        城市漫游、场景加载
        视频播放、3DGS切换
```

各层可以独立开发，但下游需要使用上游发布的稳定成果。

## 3. 各模块职责

### 3.1 Research：史料与历史复原

负责将历史文献及考古资料转化为可供三维建模使用的结构化复原数据。

主要工作：

- 解析PDF、EPUB、HTML等不同格式的历史资料。
- 建立文献检索系统，支持实体定位、章节阅读、页面阅读及语义检索。
- 检索坊市、建筑、道路及历史地名的相关记载。
- 综合多来源证据，推断空间布局和建筑形制。
- 记录复原结果的史料来源、可信度与不确定性。
- 输出标准化的空间及建筑复原数据。

当前检索系统已具备实体定位、章节/页面混合返回、指定范围内向量检索及前后页面连续阅读等能力。

**主要交付：** 结构化复原数据（JSON等格式），包括坊市边界、建筑位置、建筑属性、空间几何和证据关联。

史料层内部可使用数据库管理持续变化的研究数据，但正式交付以版本化的数据文件为主。

### 3.2 Geometry：城市几何建模

负责将史料层的结构化复原数据转换为三维城市几何模型。

主要工作：

- 构建全城空间结构、道路、坊墙及坊门。
- 根据复原数据生成坊市内部建筑及院落布局。
- 建立可复用的唐代建筑基础几何组件。
- 探索参数化与程序化建模，提高大规模城市重建效率。
- 对重点建筑进行更准确的形制与几何建模。
- 保证统一坐标系、模型尺度和建筑标识。
- 输出可供视觉加工的标准化Mesh模型。

**主要交付：** 全城白模、坊市基础模型、重点建筑几何模型及相应元数据。

几何层重点关注空间结构、建筑形制和模型完整性，不负责最终的材质、贴图及视觉效果。

### 3.3 Visual：城市视觉制作

负责在基础Mesh模型上构建完整的城市视觉效果。

主要工作：

- 唐代建筑材质与纹理制作。
- 屋顶、墙体、木构等可复用材质库建设。
- 全城视觉风格统一。
- 光照、植被、地面及环境效果制作。
- 重点建筑的高精度材质与贴图。
- 视觉模型优化与资源管理。

**主要交付：** 带材质和贴图的城市Mesh模型、材质库、纹理资源及重点建筑精细视觉资产。

视觉层应尽量独立于几何层工作，基于已发布的几何资产进行视觉加工，避免直接修改上游的几何源工程。

### 3.4 Generative：世界模型与3DGS生成

负责重点区域的生成式高精度三维场景制作。

主要工作：

- 基于历史参考图、基础几何及视觉素材生成重点场景。
- 使用世界模型生成局部可漫游的3DGS。
- 优化生成场景的真实感与视觉一致性。
- 处理3DGS的视角稳定性、场景边界与模型质量。
- 输出供场景过渡和最终展示使用的生成式三维资产。

**主要交付：** 重点区域的3DGS模型、参考图像及相关生成配置。

3DGS主要用于局部重点展示，不替代全城Mesh，也不作为历史空间结构的权威数据来源。

### 3.5 Transitions：视频与场景过渡

负责连接普通城市Mesh场景与局部3DGS场景。

本项目采用以下展示方式：

1. 用户在全城Mesh场景中自由漫游。
2. 进入重点区域后，触发场景切换。
3. 播放与当前视角衔接的过渡视频。
4. 在视频播放期间加载对应的3DGS场景。
5. 视频结束时，切换到与结束帧视角匹配的静态3DGS。
6. 用户进入局部高真实感三维场景进行漫游。

主要工作：

- 设计Mesh与3DGS之间的过渡流程。
- 确定过渡视频的首帧与尾帧约束。
- 管理相机位姿、视角匹配及坐标变换。
- 制作和处理过渡视频。
- 提供场景过渡配置与资源清单。
- 协助前端实现无明显中断的场景切换。

**主要交付：** 过渡视频、相机配置、场景映射关系及切换元数据。

Transitions与Generative可以由同一人员维护，但在项目中保持独立模块。

### 3.6 Viewer：三维展示系统

负责整合各层成果，提供完整的城市漫游与展示体验。

主要工作：

- 加载并渲染全城Mesh。
- 提供城市漫游、相机控制与交互。
- 实现多精度模型和资源加载管理。
- 集成局部3DGS场景。
- 实现视频播放与场景切换。
- 控制城市级场景的渲染性能与加载效率。

**主要交付：** 可运行的唐长安城三维漫游展示系统。

具体前端技术框架尚可根据后续开发需求确定。

## 4. 项目目录结构

**当前交付：** [唐 · 天宝长安复原](reconstructions/tang/changan-tianbao/README.md)，包含通用形制手册、平康坊和荐福寺浮图院专项资料。目前交付的是史料与复原文档，示意图不作为测绘图或制作规格。

下方是规划中的模块结构，不是当前仓库目录。后续按实际协作需要逐步增加模块工作目录。

```text
changan-revival/
│
├── reconstructions/          # 按时代和复原对象组织的交付资料
├── research/                 # 史料检索与历史复原
├── geometry/                 # 城市基础几何建模
├── visual/                   # 城市视觉及精细贴图
├── generative/               # 世界模型与3DGS生成
├── transitions/              # 视频生成与场景过渡
├── viewer/                   # 前端漫游与展示
│
├── contracts/                # 跨模块数据接口规范
│
├── data/                     # 各层正式交付的数据
│   ├── research/             # 结构化历史复原数据
│   ├── geometry/             # 基础几何资产及清单
│   ├── visual/               # 视觉资产及清单
│   ├── generative/           # 3DGS资产及清单
│   └── transitions/          # 视频与过渡配置
│
├── docs/                     # 项目整体文档
├── README.md
└── .gitignore
```

目录原则：

- 各模块主要维护自己的工作目录。
- 模块间通过`data/`中的正式交付成果进行协作。
- `contracts/`存放共享Schema、坐标约定及交付规范。
- 下游原则上不直接修改上游源文件。
- 大型模型、贴图、视频及3DGS可存放于NAS或外部资产库，在Git中记录版本及资源清单。
- 使用统一的`main`分支和短期功能分支，不使用长期独立的模块Git分支。

## 5. 数据流与版本管理

项目的核心数据依赖关系为：

```text
Research Data
     │
     ▼
Geometry Assets
     │
     ├───────────────┐
     ▼               ▼
Visual Assets    Generative Assets
     │               │
     └───────┬───────┘
             ▼
      Transition Assets
             │
             ▼
           Viewer
```

各模块应依赖上游已发布的明确版本，而非实时读取上游的内部工作状态。

例如：

- Research发布`pingkang-v001`复原数据。
- Geometry基于该版本生成平康坊基础模型。
- Visual在对应几何版本上制作材质和贴图。
- Generative根据重点建筑的几何与视觉参考生成3DGS。
- Transitions生成对应的过渡视频和相机配置。
- Viewer整合这些资产完成展示。

版本间应记录依赖关系，以支持成果追溯和重新生成。

## 6. 当前人员分工与调整方向

目前，城市几何建模、整体视觉效果调整和重点建筑高精度贴图主要集中在同一位人员身上，工作量较大，且视觉效果调整需要反复探索，容易影响城市几何建模进度。

建议调整为：

| 模块 | 建议安排 |
|---|---|
| Research | 原有史料研究人员 |
| Geometry | 原有建模人员 |
| Visual | 建议新增人员 |
| Generative | 原有世界模型人员 |
| Transitions | 可由世界模型人员与前端人员协作 |
| Viewer | 根据现有开发人员安排 |

原有建模人员已经熟悉项目及史料层的复原约束，因此继续负责几何层，与史料人员配合推进。

新增视觉人员可以在几何层持续开发期间，独立探索城市材质、贴图和视觉技术路线，待方案成熟后逐步开展全城视觉制作。

如果短期无法增加人员，应优先保障几何层交付，采用基础材质完成全城展示，将高精度视觉制作集中于少量重点场景。

上述人员调整目前属于建议方案，并非已经确定的安排。

## 7. 当前技术路线与基本原则

### 全城与局部采用不同精度

全城使用相对简化的Mesh，保证空间完整性、结构稳定性和漫游性能。

重点建筑采用更精细的几何和材质。

部分重点场景进一步使用世界模型生成3DGS，配合同视角视频实现沉浸式展示。

### 科研复原与视觉表现分离

史料层决定历史事实、空间关系与复原约束。

几何层负责实现对应的三维结构。

视觉层及生成式场景可以补充缺乏明确史料的表面细节和环境表现，但不应将视觉推测直接视为确定的历史事实。

### 优先使用可复用的模型资产

普通民居、坊墙、院落等重复性较高的建筑元素，应尽量使用组件化和程序化方式生成，避免完全依赖手工逐个制作。

### 支持各层并行开发

不要求108坊全部完成后再开始视觉制作。

史料层可以逐坊发布复原数据，几何层持续生成白模，视觉层加工已完成的基础模型，生成式场景人员同时推进重点区域。

### 分别验收科研、几何与视觉成果

史料复原、基础几何与视觉展示应有独立的交付和验收标准。

不能因为视觉效果尚未完成，就否定已经完成的史料复原和几何建模成果。

## 8. 当前阶段的工作重点

项目目前应优先推进以下事项：

1. 完善史料检索与结构化复原数据的输出能力。
2. 确定Research到Geometry的数据Schema及交付规范。
3. 建立Geometry的城市白模生成流程与基础建筑组件。
4. 明确Geometry与Visual之间的资产接口。
5. 选择代表性坊市验证从史料到视觉模型的完整流程。
6. 选择小雁塔等重点建筑，验证世界模型3DGS生成及视频衔接流程。
7. 逐步实现Viewer对全城Mesh、过渡视频和局部3DGS的统一展示。

## 9. 面向开发Agent的约定

参与本项目开发的Agent应遵守以下原则：

1. **尊重模块边界：** 优先在当前任务所属目录内修改文件，避免未经必要协商修改其他模块。
2. **优先使用正式交付数据：** 下游模块应通过`data/`读取上游成果，而非直接依赖上游的内部实现。
3. **保持接口稳定：** 修改跨模块Schema、坐标系或资产格式时，应明确受影响的模块。
4. **区分工作文件与发布成果：** 中间结果、缓存、实验资产不能直接覆盖正式交付。
5. **保留数据来源：** 几何与视觉资产应尽可能记录对应的上游数据及模型版本。
6. **避免技术过度耦合：** 不将特定建模工具、世界模型或前端框架作为其他模块的强制依赖。
7. **优先实现可运行的最小流程：** 先验证单个坊市和重点场景的端到端交付，再逐步扩展至108坊。

---

**项目总体定位：**

本项目并非单纯的古代城市三维美术制作，而是一个由历史证据驱动、以结构化空间复原为基础，通过程序化三维建模、视觉资产制作和生成式世界模型技术，实现唐长安城数字重建与交互展示的综合项目。

其核心技术路线是：

**史料约束 → 结构化复原 → 三维几何 → 城市视觉 → 局部生成式增强 → 交互展示。**
