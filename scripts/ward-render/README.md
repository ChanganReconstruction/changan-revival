# 里坊平面渲染器

从各坊的 GeoJSON 直接绘制供 agent 阅读的低位深灰度 PNG，不需要 SVG 中转。已有文档用 SVG 可按需重新生成。Node 26 直接运行 TypeScript，不需要 `tsx` 或构建步骤。

## Agent 快速上手：生成并打开 PNG

在仓库根目录运行：

```bash
pnpm install       # 首次使用或依赖更新后执行；中文字体随依赖安装
pnpm render:agent  # 生成或更新本地 PNG
```

绘图器扫描 `reconstructions/**/data/manifest.json`，自动创建输出目录。默认写入 `build/figures/agent/`，**不会在坊目录内生成 PNG，也不会修改 SVG**。PNG 和缓存不入 Git；刚检出仓库时本地图链接打不开，先运行生成命令。

若手头没有复原数据，可以直接运行随绘图器提供的[最小示例](examples/manifest.json)：

```bash
pnpm render:ward --manifest scripts/ward-render/examples/manifest.json \
  --png-dir build/figures/agent/example
```

生成 `build/figures/agent/example/ward-plan.png`；示例坐标不是历史复原结论。

### 在哪里找图

**默认批量生成时，PNG 的目录只看 `manifest.json` 的位置，不看 GeoJSON 的位置。** 取清单路径中 `reconstructions/` 和末尾 `data/manifest.json` 之间的部分，原样接到 `build/figures/agent/` 下。`changan-tianbao` 只是下例中的项目目录名，不是固定前缀。

```text
reconstructions/changan-tianbao/pingkang/data/manifest.json
→ build/figures/agent/changan-tianbao/pingkang/
```

每张 PNG 的文件名是清单里的 `outputs[].id` 加 `.png`，同一个 `id` 也用于 `--id` 筛选。`input` 只指向源数据，`output` 只供旧版 SVG 导出使用。例如李林甫宅的 `input` 在 `data/courtyards/` 下，但 PNG 和坊级总图在同一个输出目录，不会多出 `courtyards/`。

以下以平康坊清单为例。需要工作区有相应复原数据；否则可先运行上面的最小示例。

| 图 | 用于 `--id` 的值 | 默认 PNG 路径（相对仓库根目录） |
| --- | --- | --- |
| 平康坊总图 | `ward-plan` | `build/figures/agent/changan-tianbao/pingkang/ward-plan.png` |
| 李林甫宅 | `courtyard-li-linfu` | `build/figures/agent/changan-tianbao/pingkang/courtyard-li-linfu.png` |

新图建议沿用 `ward-plan`（坊级总图）、`courtyard-<对象短名>`（院落图）。`id` 用小写字母、数字和连字符，同一坊内不要重复。仅生成 PNG 时不需要填写 `output`。

### 只生成需要的图

```bash
pnpm render:agent --id courtyard-li-linfu
```

`--id` 匹配所有清单里的同名记录；如多个坊都有 `ward-plan`，会生成这几个坊的总图。只处理一个坊的清单时，用 `--manifest` 加独立的 PNG 预览目录：

```bash
pnpm render:ward \
  --manifest reconstructions/changan-tianbao/pingkang/data/manifest.json \
  --id courtyard-li-linfu --png-dir build/figures/agent/preview/pingkang
```

此例直接写到 `build/figures/agent/preview/pingkang/courtyard-li-linfu.png`，不再自动附加项目或坊名。省略 `--id` 则生成该清单的全部图。预览使用同一字体，在指定目录内单独缓存。

日志 `rendered` 表示已生成，`up to date` 表示复用已有 PNG。源数据、相关清单字段、渲染器或字体变化时会重绘受影响的图；手动删掉一张图后，重跑会补回。读图时以图例为准：灰阶与线型表示绘入几何的复原依据，不等于史料等级，也不是实测精度。

## 兼容旧版 SVG 导出和数据校验

以下 SVG 命令以有 `output` 字段的平康坊清单为例；最小 PNG 示例不包含 `output`。

```bash
pnpm render:ward \
  --manifest reconstructions/changan-tianbao/pingkang/data/manifest.json
```

也可以直接调用：

```bash
node scripts/ward-render/render.ts \
  --manifest reconstructions/changan-tianbao/pingkang/data/manifest.json
```

只校验、不写文件：

```bash
node scripts/ward-render/render.ts \
  --manifest scripts/ward-render/examples/manifest.json \
  --check
```

只渲染一个输出：

```bash
node scripts/ward-render/render.ts \
  --manifest reconstructions/changan-tianbao/pingkang/data/manifest.json \
  --id ward-plan
```

使用低色/单色主题：

```bash
node scripts/ward-render/render.ts \
  --manifest reconstructions/changan-tianbao/pingkang/data/manifest.json \
  --theme ink
```

`--theme` 对应 `styles/<name>.json`，默认 `base`。`ink` 主题用纹理区分类别；灰度 PNG 不使用 SVG 主题。

## PNG 渲染规则

灰度图不按建筑类别上色。黑色画线和字，白色留给背景和道路；坊界、墙、隅内范围和带有子要素的院界等只画轮廓。填充面按 `inference` 分配中间灰阶，线型也表示 `inference`；`grade` 仍只表示史料等级。实际填充面有 0–2 种 `inference` 时写 2-bit，3 种及以上写 4-bit。图例只显示图中实际绘制的复原依据；抗锯齿像素量化到选定灰阶，不参与位深选择。

PNG 的分辨率由绘图器计算，不使用清单的 `size`。它根据内容范围、固定字号下的标注间距、已填 `width` 的道路（目标至少 8 像素）和填充面的包围盒短边（目标至少 16 像素）求比例，单边最多 2048 像素。超过上限或标注锚点重合时会提示分区或调整锚点，不缩小文字。

## 数据约定

见[绘图器输入格式](FORMAT.md)，内含 GeoJSON 和 `manifest.json` 的最小示例、必填字段和坐标约定。仅由 `label` 要素组成的 PNG 不画地图边框，图例注明留白不表示空地。

## SVG 输出

- 输出路径由 `manifest.json` 的 `output` 决定，相对 manifest 所在目录。
- SVG 顶部带 `generated by ... do not edit by hand` 注释。
- 同一输入应产生同样输出，不在 SVG 里写时间戳。

## 边界

- 只负责平面示意图，不做测绘、剖面、3D。
- 不替代出处考证；`source` 和 `grade` 仍需人工核对。
